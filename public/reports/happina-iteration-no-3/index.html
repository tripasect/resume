گزارش ایتریشن #۳

یوزر-اپ، پرووایدر-اپ، بکند و پنل ادمین
تاریخ: ۲۹ مهر ۱۴۰۵ وضعیت: ایتریشن تکمیل شد

ایتریشنم رو تموم کردم. این ایتریشن بیشتر تست و درست‌کردن باگ بود. گزارش کارها:

پنل ادمین راحت‌تر شد

توی پنل ادمین، برای اپراتور و سوپریوزر آپلود عکس و ساخت خودکار شناسه کار نمی‌کرد. درست شد. الان برای دسته، پروفایل، استوری و ایونت می‌شه عکس آپلود کرد؛ فیلدهای مرتبط هم سرچ می‌شن.

دستیار فارسی توی ادمین

یه چت فارسی فقط برای سوپریوزر گذاشتم (دکمهٔ ؟ پایین سمت چپ). فقط سؤال جواب می‌ده؛ چیزی رو عوض نمی‌کنه. با هر دیپلوی، اطلاعاتش از خود بکند دوباره ساخته می‌شه تا کهنه نمونه.

عکس دسته با Save پاک می‌شد

اگه دسته‌ای رو باز می‌کردی و بدون تغییر ذخیره می‌کردی، عکسش پاک می‌شد. درست شد. همین مشکل برای ایونت، استوری، عکس پروفایل و عکس محصول هم بسته شد.

عکس کارت ملی توی ادمین

عکس جلو و پشت کارت ملی توی پنل ادمین لود نمی‌شد. لینک‌ها درست شدن و الان باز می‌شن.

دستهٔ آموزش توی پرووایدر-اپ

دستهٔ «آموزش» رو از ادمین اضافه کرده بودیم. API می‌فرستادش، ولی توی فرم KYC پرووایدر دیده نمی‌شد؛ چون فرانت فقط یه لیست ثابت از دسته‌ها رو قبول می‌کرد. همون باگ توی یوزر-اپ هم بود. هر دو رو برداشتم تا هر دسته‌ای که ادمین بسازه بیاد بالا.

یادداشت محل و تنظیمات ارائه

وقتی محل رو ادیت می‌کردی، فیلد یادداشت خالی می‌اومد در حالی که توی API پر بود — درست شد. تنظیمات نحوهٔ ارائه هم API درست ذخیره می‌کرد ولی صفحه می‌گفت بارگذاری ناموفق؛ یه کال الکی حذف شد و درست کار می‌کنه.

اضافه کردن عکس، سرویس رو می‌انداخت

اگه به سرویس عکس اضافه می‌کردی، کل سرویس از اپ عمومی محو می‌شد تا ادمین دوباره تأییدش کنه. الان این‌طور نیست: خود سرویس سر جاش می‌مونه؛ فقط عکس‌های جدید منتظر تأیید می‌شن. سرویسی که قبلاً افتاده رو یک‌بار توی ادمین دوباره تأیید کنید.

comment به‌جای review

طبق تصمیم تیم، مدل قدیمی review رو کنار گذاشتیم و رفتیم سراغ comment. یوزر-اپ دیگه به مسیر کهنه نمی‌زنه؛ اینباکس پرووایدر هم روی کامنت‌ها اومد.

تقویم رزرو

تقویم یوزر-اپ بعد از گرفتن داده روی لودینگ گیر می‌کرد. درست شد. تست از این لینک.

ساعت‌ها توی فرانت شیفت می‌شدن به UTC. الان همون Asia/Tehranـی که بک می‌فرسته نشون داده می‌شه.

مهمان می‌دید، لاگین‌شده ۴۰۴ می‌گرفت

بدون لاگین، جزئیات آفرینگ می‌اومد. با لاگین (اگه اکانت ارائه‌دهنده هم داشتی) ۴۰۴ می‌دادی. بکند اشتباه فکر می‌کرد فقط باید آفرینگ مال خودت رو ببینی. درست شد: هر آفرینگ قابل‌رزرو برای همه دیده می‌شه.

ادامه · رزرو، پرداخت و جمع‌بندی
تاریخ: ۲۹ مهر ۱۴۰۵ وضعیت: ایتریشن تکمیل شد
رزرو به /services/undefined/ می‌زد

تو مرحلهٔ اول رزرو، اپ نمی‌تونست شناسهٔ سرویس رو از جواب API بخونه و درخواست خراب می‌فرستاد. درست شد. اون /accounts/me بدون لاگین که جواب خالی می‌ده هم طبیعیه و جلوی رزرو رو نمی‌گیره.

چک‌اوت و مرحلهٔ بررسی نهایی

مسیر درست رزرو (/reservations) با یه مرج اشتباه دوباره برگشته بود به مسیر قدیمی (/bookings) و ۴۰۴ می‌داد — دوباره درستش کردم. بعدش صفحه روی تخفیف کرش می‌کرد چون قیمت رو از جواب API درست نمی‌خوند؛ اون هم درست شد.

برگشت از درگاه پرداخت

چند تا مشکل پشت هم بود و همه درست شدن: پرداخت موفق روی صفحه می‌موند و جلو نمی‌رفت؛ بعد از برگشت از درگاه گاهی می‌فرستادت لاگین؛ پرداخت ناموفق هم اشتباهی می‌رفت لاگین. الان موفق مستقیم می‌ره صفحهٔ موفقیت، ناموفق هم صفحهٔ ناموفق رو نشون می‌ده.

چی دیپلوی شد

بکند، یوزر-اپ، پرووایدر-اپ و گیت‌وی همه پوش و دیپلوی شدن.
